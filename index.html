Cómo construyo un servicio

Sigue una petición de punta a punta y mira dónde entra cada tecnología.

Paso 1 de 6

Llega una petición

Una app o una web le pide algo al sistema: consultar un dato o crear un registro.

Lo uso con

  • REST
  • JSON
  • Postman

Paso 2 de 6

La API la recibe sin bloquearse

Con WebFlux, un servicio atiende muchas peticiones a la vez sin dejar un hilo esperando cada respuesta.

Lo uso con

  • Spring Boot
  • WebFlux

Caso real. La migración de la plataforma de onboarding de KIIRE a Spring Boot reactivo.

Paso 3 de 6

El caso de uso decide

La lógica del negocio vive en el centro y no depende de frameworks ni de la base de datos. Así se cambia una pieza sin romper el resto.

Lo uso con

  • Arquitectura limpia
  • Hexagonal
  • SOLID

Caso real. La plataforma de experiencia de candidatos, con arquitectura hexagonal.

Paso 4 de 6

El adaptador traduce

Convierte lo que entiende el dominio en lo que entiende cada sistema externo, y al revés.

Lo uso con

  • Spring Cloud
  • Microservicios

Paso 5 de 6

Los datos quedan guardados

La información se guarda en una base de datos. Yo trabajo con relacionales y con documentos.

Lo uso con

  • PostgreSQL
  • MySQL
  • MongoDB

Caso real. KIIRE guarda sus datos en PostgreSQL sobre AWS RDS.

Paso 6 de 6

Antes de salir, todo se prueba

Pruebas unitarias, medición de cobertura y un pipeline que empaqueta y despliega.

Lo uso con

  • JUnit
  • Mockito
  • JaCoCo
  • Git
  • Jenkins
  • Azure DevOps
  • Docker
  • AWS

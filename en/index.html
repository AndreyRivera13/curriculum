How I build a service

Follow one request from end to end and see where each technology comes in.

Step 1 of 6

A request arrives

An app or a website asks the system for something: read a record or create one.

I use

  • REST
  • JSON
  • Postman

Step 2 of 6

The API takes it without blocking

With WebFlux, one service handles many requests at once without leaving a thread waiting for each answer.

I use

  • Spring Boot
  • WebFlux

Real case. The migration of the KIIRE onboarding platform to reactive Spring Boot.

Step 3 of 6

The use case decides

Business logic lives at the center and does not depend on frameworks or the database. You can swap a piece without breaking the rest.

I use

  • Clean architecture
  • Hexagonal
  • SOLID

Real case. The candidate experience platform, built with hexagonal architecture.

Step 4 of 6

The adapter translates

It turns what the domain understands into what each external system understands, and back.

I use

  • Spring Cloud
  • Microservices

Step 5 of 6

The data gets stored

Information is saved in a database. I work with relational ones and with documents.

I use

  • PostgreSQL
  • MySQL
  • MongoDB

Real case. KIIRE stores its data in PostgreSQL on AWS RDS.

Step 6 of 6

Before shipping, everything is tested

Unit tests, coverage measurement and a pipeline that packages and deploys.

I use

  • JUnit
  • Mockito
  • JaCoCo
  • Git
  • Jenkins
  • Azure DevOps
  • Docker
